# 區網 HTTPS

TalkPath 的區網模式由每份安裝環境自行產生本機 CA 與網站憑證。主機提供 HTTPS，手機端信任設定由使用者自行處理。此模式不需要網域或公開服務。

## 啟動

完成 `uv sync`、`.env` 設定與需要的 TTS／STT Docker Compose 啟動後，在專案根目錄執行：

```powershell
uv run python -m talkpath.main --lan
```

程式會監聽 `0.0.0.0`，使用 `TALKPATH_APP_PORT` 指定的埠（預設 `8000`），並列印偵測到的區網 HTTPS 位址。前端與 API 使用同一 HTTPS 來源，WebSocket 使用 `wss://`。TTS／STT 容器仍只監聽主機的 `127.0.0.1`，由 TalkPath 後端呼叫。

若主機有多張網卡，啟動時可能列出多個位址；使用手機所在區網可連通的位址。若自動偵測漏掉該 IP，可加 `--lan-ip 192.168.1.50`；此參數可重複，程式會把指定 IP 加進 HTTPS 憑證。手機與主機須位於可互通的網路，主機防火牆須允許該埠。區網模式會讓同網路裝置存取 TalkPath；目前沒有使用者帳號與存取控制，只應在可信任的區網使用。

若選用實驗性的 Pi 模式，區網啟動會把 Pi 工具的本機 API 位址設為 HTTPS，並讓 Node 信任此安裝環境的 CA。既有 `NODE_EXTRA_CA_CERTS` 檔案會與 TalkPath CA 合併；若原檔案不存在，啟動會停止並顯示檔案錯誤。

## 憑證檔案

首次區網啟動會在 `data/tls/` 建立：

- `talkpath-ca.crt`：供使用者在手機上安裝及信任的 CA 公開憑證。
- `talkpath-ca.key`：CA 私密金鑰，只留在主機上，不要傳給手機或提交到 Git。
- `talkpath-server.crt`、`talkpath-server.key`：TalkPath 的 HTTPS 憑證及私密金鑰。

這些檔案均位於 Git 忽略的 `data/` 目錄。重啟會重用同一 CA 與有效的網站憑證；區網 IP 變更或網站憑證接近到期時，只重簽網站憑證，手機已信任的 CA 保持不變。備份或移機時應成對保留 CA 憑證與私密金鑰；若只剩其中一個，程式會停止並提示恢復備份，避免無聲地更換身分。

手機能否使用錄音，仍取決於該手機是否已信任此 CA、瀏覽器是否允許麥克風，以及實際語音服務是否正常。TalkPath 不會自動修改手機的信任設定。

## 連線排查

- `--lan` 使用 HTTPS，網址須包含 `https://`；用 `http://` 連到同一埠可能出現空回應或連線錯誤。
- 主機上先使用 `https://127.0.0.1:8000/health`，正常會回傳 `{"status":"ok"}`。若 Docker／WSL 也發布 8000，`localhost` 的 IPv6 位址可能連到另一個服務；使用明確的 IPv4 位址排查。
- 手機使用啟動時列出的 `https://<主機區網 IP>:8000`，不能使用手機自己的 `localhost` 或 `127.0.0.1`。
- 憑證不受信任須安裝並信任 `talkpath-ca.crt`；連線逾時則檢查手機與主機是否可互通，以及主機目前網路類型所套用的防火牆入站規則。主機能連到自己的區網 IP，尚不足以證明手機的入站連線也已放行。
