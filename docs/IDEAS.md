- 原則：先比對原始請求與模型輸出，再決定是否調整提示詞或身分欄位處理。

### 8. 評估 MiniCPM-o-4_5 統一語音模型

- 最初記錄：2026-08-14；2026-10-02 更新服務背景。尚未實作、未技術評估。
- 現行背景：TTS 使用 Kokoro，STT 使用 qwen3-asr-service CPU OpenVINO 0.6B，已由同一份 Docker Compose 管理；仍有兩個模型服務與各自的設定及 adapter。詳見 [本機語音服務](SPEECH_SERVICES.md)。原本區網 STT 與舊 PROGRESS 的描述已不是目前狀態。
- 想法：評估以 [MiniCPM-o-4_5](https://huggingface.co/openbmb/MiniCPM-o-4_5) 作為單一模型，處理語音理解（STT／跟讀比對）與語音生成（TTS／發音播放），簡化本地依賴與對接面；模型能力與部署需求仍需技術查證。
- 待釐清：
  - 本機推理的 GPU／量化需求，或包成 local server API。
  - 僅取代 TTS＋STT，或一併評估目前外部 text provider。
  - 音質、轉錄品質與延遲如何和 Kokoro／現有 STT 實測比較。
  - 能否維持 `local_speech_services.py` adapter、`/speech/synthesize` 與 STT 端點的既有契約，只更換底層實作。
